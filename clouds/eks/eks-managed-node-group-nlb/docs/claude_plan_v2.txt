Project Plan - EKS Managed Node Group with Network Load Balancer
==================================================================

Based on the existing terraform source codes (*.tf), this project adds a Network Load
Balancer (NLB) and Target Groups (TG) in a separate terraform file, nlb.tf.

1. Target Groups (nlb.tf):
   - a Target Group is created per listener port, 80 and 443 (<name>-http-tg and
     <name>-https-tg), target_type "instance", protocol TCP, in the same VPC as the
     EKS cluster.
   - health check is TCP on the traffic port (3 healthy / 3 unhealthy thresholds,
     10 seconds interval).
   - every Auto Scaling Group (ASG) created by the module "eks" in
     "eks_managed_node_groups" (linux-small-nodes, linux-medium-nodes) is attached to
     both Target Groups via aws_autoscaling_attachment. The attachments are keyed on
     the node group keys (known at plan time), not on the ASG names (only known after
     the node groups are created).

2. Network Load Balancer (nlb.tf), attached to the Target Groups from above:
   - NLB is public facing (internal = false).
   - NLB spans all public subnets, one per availability zone, with cross-zone load
     balancing enabled, so it routes to all availability zones.
   - NLB is associated with the security group created by the module "eks"
     (module.eks.node_security_group_id), which has the rules to handle the public
     inbound ports 80 and 443 (node_security_group_additional_rules in eks.tf).
   - a listener on TCP/80 forwards to the http Target Group, and a listener on
     TCP/443 forwards to the https Target Group.
   - the public DNS name of the NLB is exposed via the "nlb_dns_name" output
     (outputs.tf).

3. File layout:
   - provider.tf - AWS provider configuration.
   - versions.tf - terraform and provider version constraints.
   - main.tf     - shared locals (name, region, AZs, VPC CIDR, tags).
   - vpc.tf      - VPC module (public, private and intra subnets, NAT gateways).
   - eks.tf      - EKS cluster, add-ons, managed node groups, and the 80/443 node
                   security group rules.
   - nlb.tf      - Target Groups, ASG attachments, NLB and listeners.
   - outputs.tf  - kubeconfig command and "nlb_dns_name".

4. Note:
   - the Target Group health checks report unhealthy until a workload listens on the
     ports 80 and 443 on the nodes, e.g. an ingress controller deployed with
     hostNetwork.
